# Week 2: MapReduce in Python

In the early 2000s, the engineers at Google were faced with the challenge of processing and analyzing vast amounts of data generated by their search engine. To address this challenge, two engineers [wrote a paper](https://dl.acm.org/doi/pdf/10.1145/1327452.1327492) introducing a programming model called MapReduce, which allows for the distributed processing of large data sets across clusters of computers. 

They realised most data processing tasks could be expressed as a sequence of two operations: a Map step, which processes and transforms the input data, and a Reduce step, which aggregates the results from the Map step. We took a look at these functions last week in brief, today we'll take a look at it in the context of big data processing.

## MapReduce

First, some assumptions:
- We have a large dataset that is too big to fit into memory on a single machine. Therefore, our dataset is distributed across multiple machines in clusters.
  - This also means we have a central controller that coordinates the MapReduce job, and multiple worker nodes that perform the Map and Reduce tasks.
- We don't want to move the datasets around the network, so we want to perform the Map and Reduce tasks on the machines where the data resides. This implies that we send the Map and Reduce tasks to the worker nodes, rather than moving the data to a central location for processing.
- Most importantly, we need to preserve the key-value structure of the data.
- The MapReduce operations should be idempotent, meaning that they can be safely retried in case of failures without causing incorrect results. This is crucial for fault tolerance in distributed systems. Idempotency implies that the Map and Reduce functions should produce the same output when given the same input, regardless of how many times they are executed (recall the pure functions we discussed last week).

### How MapReduce Works

Let's break down the process using a simple example of counting the occurrences of words in a large collection of documents. We will also implement this later on in the class. 

1. Here, we have two input files, `file1.txt` and `file2.txt`, each containing a list of words. We want to count how many times each word appears across both files. The first file contains the sentence "Tyler the Creator is undoubtedly the best rapper alive", and the second file contains the sentence "Call me if you get lost is the best album by Tyler the Creator.". 
2. In the map phase, we will read each file and emit a key-value pair for each word. The key will be the word itself, and the value will be the number 1 (indicating one occurrence of that word). For example, from `file1.txt`, we would emit pairs like ("Tyler", 1), ("the", 1), ("Creator", 1), and so on. From `file2.txt`, we would emit pairs like ("Call", 1), ("me", 1), ("if", 1), etc.
3. After the map phase, we will have a large number of key-value pairs emitted by the map tasks. The next step is the shuffle and sort phase, where the framework will group all the key-value pairs by their keys. This means that all occurrences of the same word will be grouped together. For example, all pairs with the key "Tyler" will be grouped together, all pairs with the key "the" will be grouped together, and so on.
4. In the reduce phase, we will take each group of key-value pairs and perform a reduction operation to aggregate the counts. For example, for the key "Tyler", we would sum up all the values (which are all 1s) to get the total count of occurrences of the word "Tyler". We would do this for each unique word, resulting in a final count of how many times each word appears across both files. The reducer phase then produces an output file with the final counts, such as ("Tyler", 2), ("the", 3), ("Creator", 2), etc.

This is a fairly simple example. The power of MapReduce lies in its ability to handle much larger datasets and more complex operations, such as filtering, sorting, and more sophisticated aggregations. But the tricky part is in identifying the pattern of MapReduce in the problem you are trying to solve, i.e, given a problem can you solve it using a MapReduce approach? 

### Another example

Let's say we have a dataset of Instagram posts, and we want to calculate the total number of likes for each user. Each post has a user ID and a number of likes. We can use MapReduce to solve this problem as follows:
1. In the map phase, we will read each post and emit a key-value pair where the key is the user ID and the value is the number of likes for that post. For example, if we have a post by user "user123" with 100 likes, we would emit the pair ("user123", 100).
2. After the map phase, we will have a large number of key-value pairs emitted by the map tasks. The shuffle and sort phase will group all pairs by their keys (user IDs). For example, if we have multiple posts by "user123", all pairs with the key "user123" will be grouped together.
3. In the reduce phase, we will take each group of key-value pairs and sum up the values to get the total number of likes for each user. For example, if "user123" has three posts with 100, 150, and 200 likes respectively, we would sum these values to get a total of 450 likes for "user123". We would do this for each unique user ID, resulting in a final count of total likes for each user. The reducer phase then produces an output file with the total likes for each user, such as ("user123", 450), ("user456", 300), etc.
